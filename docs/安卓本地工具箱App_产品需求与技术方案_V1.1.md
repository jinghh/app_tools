# Android 本地工具箱 App：产品需求与技术方案

-   **文档版本：** V1.1
-   **文档状态：** 需求与技术方案基线，可用于 AI
    编程助手/开发人员拆分实施
-   **目标平台：** Android
-   **核心原则：**
    原生实现、本地媒体处理、模块独立、工作流可组合、下载解析可替换
-   **重要说明：** 本文描述目标方案和待验证事项，不代表 X
    视频下载对所有帖子均可用。

------------------------------------------------------------------------

## 1. 项目概述

### 1.1 产品定位

开发一个个人使用的 Android 原生工具箱 App。第一阶段围绕 X（原
Twitter）视频处理，提供三个可独立使用的能力：

1.  从 X 帖子链接解析并下载可访问的视频。
2.  将视频截取并转换为 GIF。
3.  对已有 GIF 进行压缩，使其尽量满足用户指定的文件大小上限。

后续将增加工作流编排能力，让用户把下载、裁剪、转换、压缩、保存等模块按需组合成不同的自动化流程。

### 1.2 核心目标

-   使用 Kotlin 和 Android 原生 UI，不采用 Vue、React、WebView 或
    Capacitor 作为主应用框架。
-   视频下载、视频转 GIF、GIF 压缩是三个相互独立的功能模块。
-   所有媒体处理在 Android 设备本地完成。
-   不自建服务端，不依赖云端转码服务。
-   模块既可通过独立页面手动执行，也可被工作流引擎调用。
-   任务有进度、取消、错误提示和必要的恢复能力。
-   为后续新增媒体处理模块预留统一接口。

### 1.3 非目标

第一版不要求实现：

-   用户注册、账号系统、云端同步或服务端数据库。
-   云端视频转码、GIF 压缩或文件托管。
-   任意脚本执行或任意用户代码工作流。
-   复杂的循环、任意条件分支和可视化编程语言。
-   绕过 X 登录、付费、隐私或访问控制。
-   保证任意 X 链接、任意清晰度和任意视频都能下载成功。

## 2. 用户操作与核心流程

### 2.1 主要使用场景

用户复制一条 X 帖子链接，打开 App。App
在前台启动并获得焦点时读取一次剪贴板，识别可能的 X
链接。用户确认后开始下载；下载成功后根据视频时长执行对应流程，最后保存
GIF。

### 2.2 默认流程

1.  用户复制 X 帖子链接。
2.  用户打开 App。
3.  App 在前台读取剪贴板一次，识别并显示链接；不持续监听后台剪贴板。
4.  用户点击"开始处理"。
5.  下载模块尝试解析帖子并下载视频。
6.  下载完成后读取视频时长。
7.  视频时长不超过 30 秒：默认转换完整视频。
8.  视频时长超过 30 秒：进入片段选择界面，默认选中 0--30
    秒；用户可以直接转换前 30 秒，也可以手动调整片段。
9.  转换模块生成 GIF。
10. 压缩模块尝试将 GIF 优化至目标大小，默认 20 MB。
11. 用户预览结果并保存到可访问的位置。

### 2.3 视频时长规则

-   `duration <= 30s`：默认全片转换，不要求用户手动选择片段。
-   `duration > 30s`：默认选中 0--30s，进入片段确认界面。
-   长视频界面至少提供：
    -   "直接转换前 30 秒"
    -   "手动截取"
-   如果视频实际不足 30 秒，截取范围必须自动限制在视频时长以内。
-   片段起止时间应满足 `0 <= start < end <= duration`。
-   转换前应展示预计片段时长；用户确认后才开始生成 GIF。

### 2.4 目标文件大小与画质策略

-   默认 GIF 大小上限：20 MB。
-   用户可以在设置中修改目标大小。
-   GIF 默认参数建议：12 FPS、输出宽度 480 px、保持宽高比。
-   压缩模块应检查实际输出文件大小，不能仅根据估算值宣称已达标。
-   如果超出目标体积，可按策略逐步调整帧率、分辨率、调色板颜色数并重新编码。
-   如果达到最低可接受参数后仍无法满足限制，必须明确告知用户，并建议缩短片段或放宽大小限制。
-   不得承诺任何输入都能在任意画质要求下压到指定体积。

## 3. 功能需求

### 3.1 视频下载模块 `feature-download`

**职责**

-   接收用户输入的 X 帖子 URL。
-   校验 URL 格式并提取帖子标识（如果解析方案需要）。
-   通过可替换的解析适配器尝试获取媒体信息和可下载资源。
-   如有多个可用清晰度，展示清晰度和格式信息供选择；MVP
    可先采用默认最优可用项。
-   下载视频至 App 私有临时目录。
-   提供进度、速度（可选）、取消、失败原因和重试。
-   下载成功后输出本地文件 URI/路径以及媒体元信息。
-   不在日志中输出敏感 Cookie、令牌或完整认证头。

**重要约束**

-   X 帖子 URL 通常不是直接 MP4 地址；解析和文件下载是两个不同步骤。
-   FFmpeg 不负责解析 X 帖子链接。
-   不同帖子、登录状态、地区、限流、接口变更可能导致下载失败。
-   只支持用户有权访问的内容；不得绕过受保护账号或其他访问控制。
-   不应将某一个非官方解析接口写死在业务 UI 中。应使用独立的
    `XMediaResolver` / `DownloadProvider` 适配器。
-   下载解析方案必须通过真实公开链接测试后才能确定；不应在没有验证的情况下承诺
    yt-dlp、公开接口或其他方案一定适用于 Android。
-   如果某链接无法解析，提供清晰错误说明，并允许用户导入已下载的本地视频继续处理。

**建议的错误类型**

-   `INVALID_URL`
-   `UNSUPPORTED_URL`
-   `POST_UNAVAILABLE`
-   `AUTH_REQUIRED`
-   `RATE_LIMITED`
-   `RESOLVER_UNAVAILABLE`
-   `NETWORK_ERROR`
-   `DOWNLOAD_FAILED`
-   `STORAGE_ERROR`
-   `CANCELLED`

错误文本应面向用户，不直接显示内部堆栈；详细诊断信息可在本地调试日志中记录并脱敏。

### 3.2 视频转 GIF 模块 `feature-gif`

**职责**

-   支持导入本地视频，也支持接收下载模块输出的视频文件。
-   读取时长、宽高、帧率等媒体元信息。
-   预览视频并选择截取区间。
-   根据产品规则默认选择片段。
-   配置输出 FPS、宽度和其他可控参数。
-   使用本地媒体处理引擎生成 GIF。
-   输出 GIF 文件、实际时长、分辨率和文件大小。
-   提供进度、取消和错误提示。

**默认参数**

-   FPS：12
-   输出宽度：480 px
-   保持原始宽高比
-   片段默认规则参照第 2.3 节

**实现建议**

-   使用 Media3 ExoPlayer/相关 Media3 组件做视频预览、播放和时间定位。
-   GIF 编码建议采用经过评估的 FFmpeg Android 构建或维护中的兼容方案。
-   Media3 Transformer 可用于部分视频转码、剪辑等工作，但不能直接视为
    GIF 编码器的替代品。
-   不要直接依赖已经归档的 FFmpegKit
    官方仓库而不核查维护状态、分支、许可证和 Android 兼容性。
-   在引入 FFmpeg 前评估 ABI、包体积、许可证义务、Android API
    兼容性和构建维护成本。

### 3.3 GIF 压缩模块 `feature-gif-compress`

**职责**

-   接收一个已有 GIF 文件和目标大小。
-   独立运行，不要求该 GIF 必须由本 App 生成。
-   检查输入文件是否为可处理的 GIF。
-   优先尝试无损或低损优化；必要时重新编码。
-   输出压缩后文件、压缩前后体积、体积变化比例、实际参数和是否达标。
-   支持取消、进度、错误提示。

**建议压缩策略**

1.  先尝试 GIF
    优化（例如减少冗余帧/优化帧差分或透明区域，具体能力以所选工具为准）。
2.  如果仍超限，减少调色板颜色数并重新编码。
3.  仍超限时，逐步降低 FPS。
4.  仍超限时，逐步降低输出宽度/分辨率。
5.  每次输出后都检查真实文件大小；达标即停止。
6.  达到最低参数仍超限时，保留最后可用结果并明确提示未达标，不得静默覆盖原文件。

**数据安全**

-   默认生成新文件，不覆盖原始 GIF。
-   临时文件处理结束后清理；失败时保留必要诊断信息，但不得无限堆积缓存。
-   目标大小应统一使用明确单位：UI 显示 MB，并在内部确定采用十进制 MB（1
    MB = 1,000,000 bytes）还是 MiB（1 MiB = 1,048,576 bytes）。推荐 UI
    明确标注 MB，内部按 bytes 比较，并在文档/设置中固定换算规则。

### 3.4 本地文件模块 `core-file`

-   统一处理导入、临时文件、结果文件和文件 URI。
-   支持 Android 系统文件选择器（Storage Access
    Framework）导入本地视频/GIF。
-   处理输出文件时遵循 Android 媒体存储和 URI 权限规则。
-   用户保存结果时可使用系统文件选择器，或在适当场景下保存到公共媒体目录。
-   不应假设所有 Android 版本都能通过同一文件路径直接访问公共目录。
-   提供清理临时文件能力；不得误删用户导入文件或最终结果。
-   统一处理剩余空间不足、文件名冲突、权限被撤销等错误。

### 3.5 任务管理模块 `core-task`

-   每个任务有唯一
    ID、任务类型、当前阶段、进度、开始/结束时间、状态和错误信息。
-   状态至少包括：`PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。
-   支持取消和协作式停止；取消后清理中间产物。
-   任务进度需要区分阶段进度与总体进度，避免多个模块都从 0% 跳到 100%
    导致用户误解。
-   防止重复点击创建相同任务；允许用户在明确操作后重试。
-   需要在 App 进程被系统回收后继续执行时，按任务类型选择 Android
    合适的后台执行机制。不要把所有任务一律交给
    WorkManager，也不要默认所有长任务都能由普通协程在后台持续运行。
-   对用户主动发起、需要在切换 App 后继续的长时间任务，评估 Android
    用户发起数据传输任务、前台服务和 WorkManager
    的适用性及当前平台限制。根据目标 Android
    版本实现通知、取消入口和生命周期处理。

### 3.6 工作流模块 `feature-workflow`

**阶段一：固定流程**

先把以下固定流程实现为可执行工作流：

`输入 X 链接 → 下载视频 → 判断时长 → 选择片段 → 转 GIF → 压缩 GIF → 保存结果`

本地视频导入可使用另一条流程：

`导入本地视频 → 选择片段 → 转 GIF → 压缩 GIF → 保存结果`

**阶段二：可配置工作流**

支持用户：

-   新建、复制、重命名和删除工作流模板。
-   从已注册的模块中添加步骤。
-   调整步骤顺序、删除步骤。
-   修改各步骤参数。
-   将上一步输出作为下一步输入。
-   配置失败后停止、有限次数重试或跳过（仅限允许跳过的步骤）。
-   保存配置并在后续重复执行。

**MVP 不包含**

-   任意脚本执行。
-   用户编写 Kotlin/Python/JavaScript 代码。
-   任意循环和无限递归。
-   无限制的条件分支和动态代码加载。

**工作流安全与一致性**

-   只能调用 App 注册的模块和操作，不执行任意用户代码。
-   对每个步骤定义输入输出类型，执行前校验连接是否有效。
-   文件输出采用明确的中间产物引用，避免只传递不稳定的临时路径字符串。
-   失败后能指出失败步骤、原因以及是否保留中间文件。
-   删除模板不应删除已完成任务的结果文件。
-   工作流参数和模板保存在本地，不需要服务器。

## 4. 技术栈建议

### 4.1 技术选型

  -----------------------------------------------------------------------------------------------
  层次                    建议技术                     说明
  ----------------------- ---------------------------- ------------------------------------------
  语言                    Kotlin                       Android 主业务语言

  UI                      Jetpack Compose + Material 3 原生页面、参数表单和任务状态展示

  架构                    Gradle 多模块 +              独立模块可单测、可替换
                          清晰的领域接口               

  异步                    Kotlin Coroutines / Flow     异步执行、状态流和协作式取消

  视频预览                AndroidX Media3 ExoPlayer    本地视频播放、预览与时间定位

  GIF 编码/压缩           经评估的 FFmpeg Android      需要核查许可证、ABI、包体积和兼容性
                          构建或合适的维护中替代方案

                          MediaStore                   

  构建                    Gradle + Android SDK         生成可安装 APK

### 4.2 推荐工程结构

以下是建议的逻辑结构，具体 Gradle 模块名称可在初始化工程时调整：

``` text
app/
core/
  core-common/
  core-task/
  core-file/
  core-media/
  core-network/
  core-settings/
feature/
  feature-home/
  feature-download/
  feature-gif/
  feature-gif-compress/
  feature-workflow/
data/
  data-download/
  data-task/
  data-workflow/
```

职责边界：

-   `app`：应用入口、导航、依赖装配。
-   `core-common`：通用结果类型、错误模型、日志接口。
-   `core-task`：任务状态、任务 ID、进度与取消协议。
-   `core-file`：文件导入导出、临时文件和结果文件管理。
-   `core-media`：媒体元数据读取、媒体引擎适配。
-   `core-network`：通用网络能力，不内置特定 X 解析业务。
-   `core-settings`：本地设置。
-   `feature-*`：用户可见功能和对应业务逻辑。
-   `data-download`：X 解析适配器、下载器和资源选择策略。
-   `data-workflow`：工作流模板、步骤序列化与执行调度。

模块依赖应单向：基础模块不依赖功能模块；功能模块通过接口调用基础能力；工作流编排依赖模块接口或注册表，而不是直接依赖具体
UI 页面。

### 4.3 统一模块接口示意

可使用泛型任务接口作为设计起点，但正式实现需包含任务上下文、错误结果和取消协议：

``` kotlin
interface MediaTask<I, O> {
    suspend fun execute(
        input: I,
        context: TaskContext,
        onProgress: (TaskProgress) -> Unit
    ): TaskResult<O>
}
```

其中 `TaskContext` 建议提供任务
ID、取消信号、临时目录和日志接口；`TaskResult`
区分成功、失败和取消。具体 API
应根据各模块的输入输出类型设计，避免为了统一而强行将所有任务抽象成同一种文件输入。

### 4.4 原生性能原则

-   媒体处理在本地执行，避免上传视频进行云端转换。
-   UI 不执行耗时解码、编码或网络请求。
-   使用流式下载和合理缓冲，避免一次性把整个视频载入内存。
-   不把完整 GIF 所有帧长期保存在内存中。
-   大文件操作要支持取消，并及时释放文件描述符、解码器和临时资源。
-   通过真实设备测试性能和内存峰值，而不是只依据语言或框架名称判断性能。

## 5. X 视频解析的风险与验证计划

### 5.1 风险结论

下载功能的主要风险不是 Kotlin 或 HTTP 客户端性能，而是 X
视频资源的解析可用性和稳定性。

-   X 帖子链接通常不是直接的视频文件地址。
-   公开内容也可能因接口变更、限流、请求参数、地区或访问策略而无法解析。
-   需要登录的内容可能要求有效会话；不得绕过账号权限或访问控制。
-   非官方解析逻辑可能随 X 变化失效。
-   Windows 上的测试不能完全替代 Android 真机验证。

### 5.2 验证顺序

1.  准备 10--20 条用户有权访问的公开 X
    视频链接，覆盖不同账号、时长和视频形式。
2.  在 Windows
    环境先验证候选解析方案，记录成功率、耗时、失败原因、是否要求登录。
3.  对可行方案在 Android 真机上验证请求、下载、取消、超时和文件完整性。
4.  将解析器封装成独立接口，允许后续替换实现。
5.  只有在测试通过后，才把下载模块标记为可用；不能将少量成功案例等同于对所有帖子提供保证。
6.  对解析失败提供本地视频导入兜底路径。

### 5.3 解析器抽象建议

例如定义 `XMediaResolver`
接口，由具体实现负责解析帖子并返回媒体选项。业务 UI
只依赖接口，不依赖某个特定网站、第三方 API 或解析库。

解析结果应包括可用媒体选项、清晰度/格式（若可获得）、过期时间或有效期提示（若可确定）以及可读错误类型。媒体
URL 可能具有时效性，应尽快下载，不应默认永久保存或长期复用。

## 6. 交互与页面规划

### 6.1 首页

-   展示三个核心工具入口：视频下载、视频转 GIF、GIF 压缩。
-   展示工作流入口。
-   前台进入时检查剪贴板一次；如果识别到 X
    链接，显示链接预览和"开始处理"操作。
-   不在后台持续读取剪贴板。
-   提供本地视频/GIF 导入入口。

### 6.2 视频下载页面

-   URL 输入框与粘贴操作。
-   链接格式检查。
-   解析中、可下载、下载中、完成、失败状态。
-   如可获得多个清晰度，允许选择；MVP 可使用默认可用清晰度。
-   进度、取消、重试。
-   下载成功后可预览视频或继续转 GIF。

### 6.3 视频转 GIF 页面

-   视频预览和媒体信息。
-   起止时间选择。
-   超过 30 秒时默认选中 0--30 秒并要求确认片段。
-   FPS、输出宽度等参数。
-   预计片段时长和开始转换操作。
-   转换进度、取消、预览结果。

### 6.4 GIF 压缩页面

-   导入 GIF。
-   展示原始体积、目标体积和可配置压缩策略。
-   展示压缩进度。
-   展示压缩前后大小、是否达标、参数变化。
-   保留原文件，不默认覆盖。

### 6.5 工作流页面

初期只展示预设工作流并允许运行。后续增加模板管理、步骤排序、参数编辑、输入输出校验、失败策略和保存功能。

## 7. 隐私、安全与可靠性

-   默认所有视频和 GIF 均在设备本地处理。
-   不将用户的文件、链接或任务历史发送到自建服务器。
-   下载 X 视频本身需要联网，且会向 X
    或相关资源主机发出请求；因此不能宣传为完全离线。
-   不将认证信息、Cookie、完整请求头写入日志。
-   不尝试绕过登录、付费、私密账号或其他访问控制。
-   剪贴板只在 App 前台合适时机读取一次，并向用户展示识别结果。
-   只申请完成目标功能所需的权限；优先使用系统文件选择器和 URI 授权。
-   下载和转换失败时清理不再需要的临时文件。
-   通过实际设备测试低存储空间、网络断开、进程回收、权限撤销和取消操作。
-   提供明确的失败提示，不把解析失败误报为网络失败，也不把未达标的 GIF
    标记为压缩成功。

## 8. 验收标准

### 8.1 模块独立性

-   下载模块可独立输入 URL 并输出本地视频文件或明确错误。
-   GIF 转换模块可独立导入本地视频并生成 GIF。
-   GIF 压缩模块可独立导入已有 GIF 并生成压缩结果。
-   任意一个模块失败，不应导致其他模块无法单独使用。
-   更换 X 解析器不应要求重写 GIF 转换和压缩模块。

### 8.2 时长规则

-   30 秒及以下视频默认选择完整视频。
-   超过 30 秒的视频默认选择前 30 秒。
-   用户可直接转换前 30 秒，也可进入手动截取。
-   起止时间不越界，短视频不会因默认 30 秒而出现无效区间。

### 8.3 GIF 压缩

-   默认目标大小为 20 MB。
-   每次输出后检查实际字节数。
-   达标时报告实际体积。
-   无法达标时明确显示未达标及建议措施。
-   默认不覆盖原始文件。

### 8.4 任务控制

-   主要长任务显示状态和进度。
-   用户可以取消任务。
-   取消后停止后续工作并清理不再需要的中间产物。
-   网络错误、解析失败、存储不足和媒体处理失败应有可区分的错误提示。

### 8.5 工作流

-   固定工作流可以依次执行下载、转 GIF、压缩和保存。
-   步骤输出能够传给下一步骤。
-   步骤失败时可以定位失败步骤。
-   后续用户自定义工作流只允许选择已注册模块，不执行任意代码。

## 9. 分阶段实施计划

### 阶段 0：技术验证

-   创建 Kotlin 原生空项目。

-   验证 10--20 条公开 X 视频链接的解析成功率。
-   核查第三方组件许可证、维护状态、ABI 和包体积。
-   输出验证结果，再确定下载模块最终实现。

### 阶段 1：本地媒体 MVP

-   完成文件导入和本地视频预览。
-   完成片段选择和 30 秒规则。
-   完成视频转 GIF。
-   完成 GIF 目标体积压缩。
-   完成结果预览、保存、取消和错误处理。

-   接入经验证的 X 解析适配器。
-   完成视频资源选择和本地下载。

### 阶段 3：固定工作流

-   完成失败定位与清理逻辑。

### 阶段 4：自定义工作流

-   工作流模板的新增、复制、重命名、删除。
-   添加、删除、排序步骤。
-   编辑步骤参数。
-   输入输出类型校验。
-   保存和重复运行工作流。
-   根据实际需求再评估条件分支和更高级的编排功能。

## 11. 开发时必须遵守的工程原则

1.  **先验证风险最大的技术点。** 不要在 X
    下载方案尚未验证时就围绕某个解析器构建全部业务。
2.  **模块独立，接口稳定。** UI 不直接调用 FFmpeg 命令或 X
    解析细节；通过领域接口发起任务。
3.  **本地优先。** 除了访问 X
    下载资源所需的网络请求，媒体转换、压缩、配置和工作流均在本地执行。
4.  **处理实际结果，而非只依赖估算。** GIF 压缩必须检查实际文件大小。
5.  **资源可控。**
    长任务支持取消，媒体处理及时释放资源，临时文件有明确生命周期。
6.  **工作流只组合受控模块。** 不执行任意脚本或动态加载未知代码。
7.  **错误可诊断。** 统一错误类型、任务 ID
    和脱敏日志；用户提示应清晰可操作。
8.  **不要为了抽象而过度设计。**
    先做三个可独立使用的模块和固定工作流，再根据真实使用需求增加复杂能力。
