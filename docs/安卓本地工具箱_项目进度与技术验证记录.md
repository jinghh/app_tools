## 1. 项目定位回顾

个人使用的 Android 原生工具箱 App。第一阶段三个独立能力：

1. 从 X 帖子链接解析并下载视频（阶段 2，未开始）；
2. 将视频截取并转换为 GIF（阶段 1，**已实现并真机验证**）；
3. 对已有 GIF 压缩至目标大小上限（阶段 1，**已实现，待真机测试反馈**）。

核心原则：原生实现（Kotlin + Jetpack Compose）、本地媒体处理、模块独立、工作流可组合。

### 2.3 真机测试数据

- **测试设备：** 荣耀 DNP-AN00 · Android 16 · arm64-v8a
- **用例：** 5s 视频，8fps，320px 宽，256 色，Bayer 抖动
- **结果：** FFmpeg 输出 2.09MB / 耗时 11.5s（约 2.3 倍实时，GIF 编码正常水平）；Java 引擎 2.13MB / 331s（弃用）
- **已知待观察：** 36MB 级输出的级联压缩效果（需压缩模块测试数据）

### 2.4 版本锁定理由（写在 gradle/libs.versions.toml 注释中）

1. FFmpegKit 必须锁定精确版本号（`8.1.9`），禁用 `+`（会跨 LTS 线跳版本）；
2. Compose BOM 锁 2025.10.00：更新的 BOM 要求 AGP 9.1.0+ / compileSdk 37，升级需单独评估 AGP 9 的 built-in Kotlin 变更；
3. compileSdk 36：依赖链（media3 1.11.1 / activity-compose 1.13.0）的最低要求。

### 2.5 发布约定（防止"版本号与内容不一致"）

**已发生的真实问题**：tag `v0.1.1` 指向较早的提交 `d3b9009`，但之后又合入了 3 个提交
（自动提取链接、Cookie 导入、复制日志）却**未提升版本号**，导致"同一个版本号 `0.1.1`
对应两批不同代码"——GitHub Release 的内容落后于本地和手机，用户无法通过版本号分辨。

约定（每次发版必须遵守）：

1. **tag 名 = `v` + `versionName`**：如 `versionName = "0.1.2"` → tag 为 `v0.1.2`；
2. **必须递增 `versionCode`**（同一 versionCode 无法覆盖安装）；
3. **推 tag 前逐项确认**：`versionName` 已提升、待发布内容已全部提交、`git status` 工作区干净。

### 3.2 已验证通过的功能

- SAF 导入本地视频/GIF（零运行时权限，全程系统文件选择器）；
- 视频播放与时间定位；
- 30 秒片段规则（≤30s 全片；>30s 默认前 30s，可调整）；
- 视频转 GIF（fps/宽度/颜色数/抖动参数，进度、取消、结果校验）；
- GIF 压缩（原参数重编码 → 128/64/32 色 → 8/6fps → 480/360/240px 级联，每轮真实字节数校验，达标即停；未达标保留最后可用结果并明确提示；原文件只读）；
- 结果保存（CreateDocument 导出）；
- **视频下载（多站点）**（真机已验证）：X、Facebook、小红书可下载（支持粘贴分享文本自动提取链接）→ 直传转 GIF；YouTube 不可用（403）；
- **后台下载保活**（真机验证通过）：下载跑在进程作用域 + `DownloadService` 前台服务中，切到后台不再被系统冻结/回收；
- **下载通知**：进度通知（低优先级、静音、常驻）+ 完成/失败结果通知（可点击回到下载页）；
- **通知提醒可选**：App 内开关控制结果通知，另提供系统通知设置入口；关闭后仍可正常下载（进度通知受前台服务强制要求，无法单独关闭）。

### 3.3 开发过程中修复的问题（Code Review 记录）

| # | 问题 | 修复 |
|---|---|---|
| 1 | `extractString` API 不存在（应为 `extractMetadata`） | 编译期捕获并修正 |
| 2 | 取消标志跨任务"粘住"（引擎实例复用未复位） | `encode()` 入口复位 |
| 3 | FFmpegKit 取消后终态事件重复发送 | AtomicBoolean 去重（后由 Runner 统一收敛） |
| 4 | 抽帧失败不删半成品输出 | 失败路径补 cleanup |
| 5 | SAF 文件名未消毒（路径穿越风险） | `sanitizeFileName` |
| 6 | 体积显示 MiB/MB 混淆 | 统一十进制 MB（1MB=1,000,000B） |
| 7 | 原生库缺失时未捕获异常会崩溃 | UI 层统一 try/catch 兜底 |
| 8 | `.gitignore` 的 `/build/` 只匹配根目录，`app/build/` 会被误提交 | 改为 `build/` |
| 9 | `getScaledFrameAtTime` OEM 返回尺寸不精确（已随 Java 引擎移除） | 尺寸归整校验（历史修复） |
| 10 | 用 `--print` 取 yt-dlp 输出（库不转发 stdout）→「解析」必失败 | 先改 `--write-info-json` 落盘；**真机仍失败后查实参数白名单**（该类参数不在白名单），最终删除解析路径 |
| 11 | 重构时把下载绑定在解析成功上，解析失效会丧失已实测的下载能力 | 补兜底入口（后随解析路径一起收敛为单一可用路径） |
| 12 | OkHttp 5.5.0 要求 compileSdk 37（本机上限 36.1） | 曾锁 4.12.0；解析路径删除后该依赖一并移除 |
| 13 | yt-dlp AAR 注入存储权限，且合并器自动推导 `READ_EXTERNAL_STORAGE` | 两者均 `tools:node="remove"` |
| 14 | 保存成功无任何可见提示（仅日志） | 三个页面保存流程均加 Toast 提示（成功/失败） |
| 15 | yt-dlp 以 Python 异常形式失败时，未走中文映射，直接把英文原始报错（含超长 URL）展示给用户 | 异常路径同样经过错误映射；兜底文案不再外泄原始文本，完整内容仅留在诊断面板 |
| 16 | 小红书分享文案夹带中文推广语，直接粘贴必然失败 | 新增 `UrlExtractor`：粘贴即自动只保留链接（含尾部中文标点清理），下载前再兜底抽取一次 |
| 17 | 需登录的内容（小红书部分笔记）会跳转登录页导致 `Unsupported URL` | 新增 Cookie 导入（Netscape cookies.txt → `--cookies`），以用户自身登录态访问其有权查看的内容 |
| 18 | **下载状态挂在 Compose 界面作用域**：切后台进程被冻结/回收后下载失败，且界面重建后结果丢失 | 提升到 `DownloadCenter` 进程作用域（`StateFlow`）+ `DownloadService` 前台服务（`dataSync` 类型） |
| 19 | 下载成功后还会补一次元信息更新，产生**第二次 SUCCESS 发射** → 重复弹出「下载完成」通知 | 终态按"阶段变化"去重 |
| 20 | 上一条去重**把 `RUNNING` 也去重了**，导致进度通知卡在初始值不动 | 改为进度每次都更新，**只有终态去重** |
| 21 | 收集器写在 `onStartCommand`：`stopSelf()` 后服务被复用会出现**两个收集器** → 重复结果通知 | 收集器移到 `onCreate`（每个服务实例只启动一次） |
| 22 | `formatBytes` 位于 `ui` 包，被 `download` 复用会形成 `ui ↔ download` **包级循环依赖** | 移到中性位置 `util/Format.kt` |
| 23 | 下载页输入框无法快速清空 | 增加尾部清除按钮（有内容且非下载中时显示；下载中输入框整体禁用故隐藏） |
| 24 | 通知开关若做成"假开关"（App 无法自行授权/撤销权限）会误导用户 | 拆成两层：App 内偏好（结果通知，可持久化）+ 系统权限入口；开关打开但权限被拒时状态文字变红明确告知 |

### 阶段 2：下载模块 —— 🔄 进行中（解析候选已验证可用）

**候选评估：`dev.ffmpegkit-maintained:yt-dlp-android:2.0.2`（已选中，真机验证可用）**

| 核查项 | 结论 |
|---|---|
| 实现方式 | 内嵌完整 CPython 3.13（Chaquopy 17）+ yt-dlp；非纯 Java |
| 依赖接入 | 单依赖即可；Chaquopy 的 Java API 随 AAR 的 `libs/chaquopy_java-17.0.0.jar` 提供（已核实可编译） |
| 许可证 | MIT（wrapper）；yt-dlp 本体 Unlicense |
| 兼容性 | minSdk 24 ✓ · arm64-v8a + x86_64 · **16KB 页对齐实测通过**（`0x4000`）· 无 AGP/compileSdk 约束 |
| 真机结果 | ✅ **X（Twitter）**；✅ **Facebook 公开视频**；⚠️ **小红书**：公开笔记可下，需登录的笔记会跳转登录页而失败；❌ **YouTube 返回 403**（需 TLS 指纹伪装或 JS 运行时解签名挑战，免费版均不具备） |
| 分享文本处理 | 小红书等站点复制的分享文案夹带中文推广语（如「…来【小红书】发现这篇笔记的精彩~」），已增加自动提取链接功能（`UrlExtractor`），输入框只保留 URL |
| 登录态支持 | 新增 Cookie 导入（`CookieStore`，Netscape cookies.txt → `--cookies`，该参数在库白名单内），用于小红书/微博等需登录的站点；文件存于应用私有目录，日志侧有敏感词过滤 |
| 体积 | APK 50.7MB → 88.1MB（双 ABI）→ **58.4MB（仅 arm64-v8a 后）** |
| 权限治理 | AAR 注入 `WRITE_EXTERNAL_STORAGE`，且合并器会自动推导 `READ_EXTERNAL_STORAGE` → 均已 `tools:node="remove"` 剔除 |

**已核实的库能力边界（决定架构设计，非猜测）**：

1. `YtDlpResponse` 的 output/error **恒为空串** → 取不到 stdout/stderr；
2. 运行器把 CLI 参数转成 YoutubeDL **opts 字典**，且**只转发自定义 logger 的日志、不转发 stdout**；
3. **CLI 参数白名单**（从运行器字节码提取，最终结论的依据）：
   `--format --output --cookies --proxy --add-header --user-agent --restrict-filenames
    --newline --no-playlist --extract-audio --audio-format --audio-quality
    --write-sub --sub-lang --merge-output-format`
   ⇒ `--print` / `-J` / `--write-info-json` / `--skip-download` **均不在白名单**（静默丢弃）
   ⇒ **下载前无法获得标题/时长/清晰度/直链**（真机实测「解析」必然失败，已据此移除该路径）；
4. **无取消 API**，`Future.cancel` 无法中断内嵌 Python → 取消为“放弃等待”（PRD 8.4 在此实现下不满足）；
5. yt-dlp **无法应用内更新** → X 接口变化需重新打包发版。

**当前架构（务实回归：只保留一条实测可用路径）**：

```text
download/
    XMediaResolver.kt    # 解析器接口 + MediaOption + ResolveError（PRD 3.1 错误类型子集）
                         # 有意留空实现：yt-dlp 无法承担解析职责，待自研解析器补齐
    YtDlpDownloader.kt   # 下载实现：yt-dlp 直下（含进度；取消为放弃等待）
    DownloadCenter.kt    # 进程级状态中心：下载脱离界面生命周期，切后台/界面重建都不丢
    DownloadService.kt   # 前台服务（dataSync）：进程保活 + 进度通知 + 结果通知
    NotificationPrefs.kt # 通知偏好 + 系统权限状态（App 无法自行授权/撤销，只能引导）
    DownloadEvent.kt     # 事件模型
```

- 流程：输入链接 → 下载（yt-dlp）→ **下载后本地读取时长/分辨率** → 「去转 GIF」直传转换模块；
- 「去转 GIF」跨页签传文件已验证可用，免去手动保存再导入；
- 曾尝试的「解析按钮 / 格式选择 / OkHttp 可取消下载」因上述能力边界**已回滚删除**，
  待自研解析器（直接解析公开帖子取 media URL）落地后恢复；设计方案已记录在本文件。
